# AGENTS.md

Working notes for this repo. Read this before changing anything.

## What this is

A habit tracker: sign up, create habits, tick them off daily, build a streak.
University capstone, so parts of it are deliberately unfinished — see
[Hand-write zones](#hand-write-zones) before "fixing" anything that looks
missing.

## Data model

Defined in [`supabase/schema.sql`](supabase/schema.sql).

**`habits`** — `id`, `user_id` (default `auth.uid()`, FK → `auth.users`,
cascade), `title` (1–80 chars), `description` (≤280), `is_active`,
`created_at`.

**`daily_logs`** — `id`, `habit_id` (FK → `habits`, **cascade**), `user_id`
(default `auth.uid()`, cascade), `log_date`, `completed`, and
`unique (habit_id, log_date)`.

Two things follow from that:

- **Deleting a habit deletes its whole history.** The cascade is why the
  delete dialog says so out loud.
- **The unique constraint is what makes ticking idempotent.** Ticking upserts
  with `onConflict: 'habit_id,log_date'`, so a second tick updates rather than
  colliding — which means the write needs *both* the INSERT and UPDATE
  policies on `daily_logs` to pass.

`user_id` on `daily_logs` duplicates what `habit_id` could reach. That is
deliberate: it lets a policy check ownership without joining back to `habits`.

Dates are computed client-side (`todayISO()`), not left to the `current_date`
default, which is UTC. Far enough from UTC, a habit ticked at 9pm would land on
tomorrow's row.

### SQL run order

1. `schema.sql` — tables, indexes, constraints
2. `policies.sql` — RLS (hand-written)
3. `seed.sql` — optional; replace both `REPLACE_ME` emails with a real account
4. `schema_v2.sql` — `profiles`, signup trigger, backfill, RLS switched on
5. The `profiles` policies (hand-written, see [zone 5](#5-profiles-rls--filters))
6. `storage.sql` — `avatars` bucket and its storage policies

Between 1 and 2 the tables have no RLS. Do not point the app at a database in
that state. Between 4 and 5 `profiles` has RLS on and no policies — safe
(everything is denied), but the app sees no profile row.

## Auth flow

[`AuthProvider`](src/context/AuthProvider.jsx) holds the session, fed by
`getSession()` on mount and `onAuthStateChange` thereafter. Its cleanup both
unsubscribes and invalidates the in-flight request, because StrictMode mounts
effects twice in dev.

`loading` starts `true` and only clears once the first answer arrives. Routes
must not decide anything while it is true — redirecting on an unknown session
throws signed-in users out on every refresh.

- [`ProtectedRoute`](src/routes/ProtectedRoute.jsx) — skeleton while loading,
  else `<Navigate to="/login" replace>` carrying the attempted path in
  `state.from`.
- [`PublicOnlyRoute`](src/routes/PublicOnlyRoute.jsx) — the mirror; signed-in
  visitors to `/login` or `/signup` go to `state.from ?? '/'`.

Sign-up with email confirmation enabled returns a user but **no session**.
`signUp()` reports that as `needsEmailConfirmation` and the page shows a
"check your inbox" panel — otherwise the form looks like it did nothing.

## Design rules

Tokens live in `:root` in [`src/index.css`](src/index.css). Use them; do not
hardcode colours or radii in components.

**Colour.** Each brand hue exists twice:

- `--x-bright` — the exact brand colour. **Never place text on it.**
- `--x` — same hue, darkened until white text clears 4.5:1.
- `--x-edge` — darker still, for the 3D press edge.

This split exists because the brand colours fail WCAG AA behind white text
(`#58CC02` measures 2.1:1, `#1CB0F6` 2.5:1, `#FF9600` 2.2:1, `#FF4B4B` 3.3:1).
Bright is for ticks, progress, the flame, focus glow. Fill is for anything
carrying a label.

**Shape.** `rounded-card` (16px) for cards, `rounded-control` (12px) for
buttons and inputs. Minimum 48px tap targets — `size="touch"` on Button,
`h-12` on Input.

**The 3D button** is a `box-shadow`, not a real border, so shrinking it on
`:active` does not reflow the row. Hover *lifts* rather than lightening the
fill, so measured contrast holds in every state. Variants: `brand`, `sky`,
`danger`, `quiet`.

**Every async view needs three states**: skeleton while loading, `ErrorState`
with a retry, `EmptyState` when the query succeeded and returned nothing. An
empty list is not an error and must never be shown as one.

**Accessibility is not optional here.** Visible focus rings, a label on every
input, `aria-describedby` pointing at error text, `role="alert"` on errors that
appear, keyboard reachable throughout. Motion respects
`prefers-reduced-motion` via a global block in `index.css`.

Copy is warm and short: "Nice! Habit added.", "No habits yet. Start your first
one!". No Duolingo logos, mascots or assets — the general feel only.

## V2: avatars and error boundaries

### `profiles` table

Defined in [`supabase/schema_v2.sql`](supabase/schema_v2.sql). `id` (PK, FK →
`auth.users`, cascade), `avatar_url`, `updated_at`. One row per user, keyed by
the user's own id — so policies compare `auth.uid()` with **`id`**, not
`user_id`.

- **Trigger** `on_auth_user_created` → `public.handle_new_user()` inserts a
  row on every signup. It is `security definer` (there is no session at signup,
  so it must bypass RLS) with `set search_path = ''` and schema-qualified names.
  The client therefore never inserts its own profile.
- **Backfill** in the same file creates rows for accounts that predate the
  trigger. Re-running is harmless.

### `avatars` bucket

Defined in [`supabase/storage.sql`](supabase/storage.sql).

| Setting | Value | Why |
| --- | --- | --- |
| `public` | `true` | `<img src>` works without a token. Reads only — writes still need a policy. |
| `file_size_limit` | `1048576` (1 MB) | Server-side twin of the client's size check |
| `allowed_mime_types` | jpeg, png, webp | Server-side twin of the type check. No SVG — it can carry script. |
| Object path | `<uid>/avatar` | Fixed name, **no extension**, so upsert replaces rather than accumulates |

The bucket limits are the **backstop**: `validateAvatar` runs in the browser and
anyone can skip it by calling the Storage API directly. Note the MIME check
trusts the `Content-Type` the uploader sends; nothing server-side inspects the
bytes.

**Storage policies** — four on `storage.objects` (select, insert, update,
delete), all `to authenticated`, every one requiring **both**:

```sql
bucket_id = 'avatars'
and (storage.foldername(name))[1] = (select auth.uid())::text
```

Without the folder check, any signed-in user can overwrite anyone's avatar.
Without the bucket check, the policy applies to every bucket. Update carries
the check in both `using` and `with check`. Upsert needs insert + update +
select together.

### Upload flow

[`src/lib/profile.js`](src/lib/profile.js) — `getProfile()`, `uploadAvatar(file)`.
Neither takes a user id: both read it from the session, so no caller can aim
a path or a query at someone else.

1. `AvatarUploader` → `validateAvatar(file)`. Failure → inline error under the
   input (`role="alert"`, `aria-describedby`), **no request made**.
2. Preview via `URL.createObjectURL`, created in the change handler, revoked by
   an effect cleanup whenever it changes and on unmount.
3. `upload('<uid>/avatar', file, { upsert: true, contentType: file.type })`.
4. `getPublicUrl` + `?v=<Date.now()>` — the path never changes, so without the
   cache-buster browsers keep showing the old image.
5. `update profiles set avatar_url` for the user's own row.

State lives in [`ProfileProvider`](src/context/ProfileProvider.jsx) (via
`useProfile`), mounted around `TrackerPage` inside the protected route, so the
header avatar and the uploader share it. Loading → skeleton; load error →
`ErrorState` + retry; no avatar → initials + "No photo yet"; upload error →
inline message + Retry; success → toast.

### Error boundaries

`ErrorBoundary` (hand-written, zone 4) with `name`, `fallback` (node or
`({ error, reset, name }) => node`) and `resetKeys`. Fallbacks use
[`SectionFallback`](src/components/app/SectionFallback.jsx) — friendly copy and
Try again, never the error message or stack.

| `name` | Wraps | File | `resetKeys` |
| --- | --- | --- | --- |
| `nav` | Header contents (compact fallback) | `AppShell.jsx` | — |
| `avatar` | `AvatarUploader` | `TrackerPage.jsx` | — |
| `stats` | `StatsSection` | `TrackerPage.jsx` | `[habits, doneToday]` |
| `habits` | Habit list | `TrackerPage.jsx` | `[habits]` |
| `app` | All `<Routes>` — last resort only | `App.jsx` | — |

**Boundaries only catch errors thrown while rendering.** Event handlers, async
code (`await`, promises, timers) and errors in the boundary's own fallback are
not caught. Those still need `try/catch` + `toast` (or an error state that
renders `ErrorState`) — which is what every handler in `TrackerPage` and
`AvatarUploader` already does. Do not remove those on the theory that a
boundary covers them.

### CrashTest (removed)

A dev-only `<CrashTest />` that threw during render on `?crash=<section>` was
used to screenshot the boundaries, then removed. To test a boundary again,
temporarily render a child that throws inside it — the throw must happen
during render; one in an event handler or after an `await` will not reach the
boundary.

**UpdateToast** — [`src/components/app/UpdateToast.jsx`](src/components/app/UpdateToast.jsx).
The import is exactly `import { useRegisterSW } from 'virtual:pwa-register/react'`

### Sign-out clears runtime caches

A service-worker cache is keyed by URL, not by user, and outlives the session.
[`clearRuntimeCaches()`](src/lib/pwa.js) deletes every cache **except**
`workbox-precache-*` (so the app still opens offline for the next person) —
by "not the precache", so it works whatever names zone 6 picks. It runs:

- awaited in `AuthProvider.signOut()`, before `/login` renders;
- on every `SIGNED_OUT` event — signing out in another tab, or the session
  ending on its own.

It cannot help a tab closed without signing out. That is why zone 6 has to
weigh caching `/rest/v1` at all.

### Offline queue (habit creation only)

[`src/lib/offlineQueue.js`](src/lib/offlineQueue.js), used by `useHabits`.

- **When it queues** — `create()` queues if `navigator.onLine` is false, **and**
  if the insert fails with a network error (`isNetworkError`): `onLine === true`
  does not prove a connection.
- **Storage** — `localStorage['habit-tracker:queue:<userId>']`. Per user.
- **Idempotency** — each item gets `crypto.randomUUID()` up front, sent as the
  habit's primary key. A replay hits `23505` and counts as synced. Online
  creates send the same id they would queue with, so a request whose response
  was lost cannot duplicate either. No schema change needed.
- **Sync** — on the `online` event and on start-up. One run at a time
  (module-level promise), one item at a time, oldest first. Re-checks the live
  session user before every insert and stops if it changed. Removes an item
  only after its insert succeeds; a network error stops the run; any other
  error keeps the item with `lastError` (Retry / Discard on the card). Then
  refetches. Toasts: "Saved offline, will sync when you're back online" and
  "Back online. Synced N habits."
- **Never** sends `user_id` — column default + INSERT policy apply as normal.
- **Sign-out** clears the queue (`AuthProvider.signOut`). `UserMenu` asks first
  if anything is unsynced.
- **Everything else** (tick, edit, delete, avatar save) is disabled while
  `useOnlineStatus()` is false; if the browser lies, `friendlyDataError` shows
  "You're offline".

Queued items render as [`QueuedHabitCard`](src/components/app/QueuedHabitCard.jsx):
clock icon, dashed, muted, "Queued", no controls. They are not counted in
stats.

### Responsive rules

- Test at **320** (iPhone SE), **393** (Pixel 5), **768** (tablet): no
  horizontal scroll — `document.documentElement.scrollWidth > innerWidth`
  must be `false`. Fix causes, never `overflow-x: hidden` on the page.
- Flex children that hold text get `min-w-0` + `truncate`.
- Card grids start at `grid-cols-1` and widen at `sm:`. (Stats: `sm:grid-cols-3`
  — three tiles in two columns strands one.)
- `overflow-x-auto` only inside tables or code blocks.

  `min-h-12` on `DropdownMenuItem` (the generated ones are ~28px).
- Inputs are `text-base` (16px) — smaller and iOS zooms on focus.
- Safe areas: `safe-x`, `safe-top`, `safe-bottom` utilities in `index.css`

- Alert dialogs: `max-sm:max-w-[calc(100%-2rem)]!` — the generated `max-w-xs`

**Share** — [`ShareButton`](src/components/app/ShareButton.jsx) in the header.

Shares only `location.origin + '/'` and fixed copy — never the current URL,

## Hand-write zones

**write these for student for better grades** If you are an agent and asked to
"finish" or "fix" them, explain it and explain to them clearly.

### 1. RLS policies — `supabase/policies.sql`

The `alter table ... enable row level security` lines may be written. The
`CREATE POLICY` statements may not. Eight of them, four per table.

Reviewing them is fine. Writing them is not.

### 2. Query filters — `src/lib/habits.js`

Every `.eq(...)` is left as a `// HAND-WRITE:` comment naming its target.
Six markers across five functions:

| Function | Filter |
| --- | --- |
| `listHabits` | `.eq('user_id', userId)` |
| `listLogsSince` | `.eq('user_id', userId)` |
| `updateHabit` | `.eq('id', habitId)` |
| `deleteHabit` | `.eq('id', habitId)` |
| `unlogHabitToday` | `.eq('habit_id', habitId)` + `.eq('log_date', date)` |

The file has an `/* eslint-disable no-unused-vars */` at the top, because the
unused arguments *are* the missing filters. Delete it once every marker is
filled — anything still reported unused then is a marker that was missed.

**⚠ These functions run as written.** With the filters missing, deleting one
habit deletes all of them and unticking one day clears every log. That is the
point of the exercise, not a bug to patch.

### 3. Avatar validation — `src/lib/validateAvatar.js`

The whole file. `async validateAvatar(file) → { ok, error? }`, plus the
exported `MAX_AVATAR_BYTES` and `ALLOWED_AVATAR_TYPES` that `AvatarUploader`
imports. Four guards in order: file present and non-empty; MIME type on the
allowlist; size ≤ 1024 × 1024 (inclusive); magic bytes (PNG / JPEG / WebP)
match and agree with `file.type`.

### 4. Error boundary — `src/components/app/ErrorBoundary.jsx`

The whole class: `getDerivedStateFromError`, `componentDidCatch` (dev-only

## Security rules

- **Anon/publishable key only.** `service_role` never appears in this repo, in
  `.env`, or in any client code. It bypasses RLS entirely.
- **The anon key is public.** It ships inside the JS bundle. Anyone can read it
  out and call the REST API directly. RLS is the only thing between that key
  and the data.
- **Never send `user_id` from the client.** Let the `auth.uid()` column default
  set it. A client-supplied owner is a claim, not a fact.
- **Scope every query to the signed-in user** even though RLS also does. The
  query should state its intent.
- **Know where RLS does and does not help.** It stops other people touching
  your rows. It does nothing about you touching too many of your own — an
  unfiltered `delete` removes every row you own, and RLS permits all of it.
- **RLS is the last line of defence, not the first.** Client-side checks are
  for feedback; the database is what enforces.

## Git rules

- **Never run `git add`, `commit`, `push`, `rebase` or `tag`.** Print the
  commands and let the human run them. `.claude/settings.json` denies these at
  the tool level as well.
- **No AI attribution.** No `Co-Authored-By` trailer, no "Generated with"
  footer. `.claude/settings.json` blanks both.
- Before every commit, confirm `.env` is absent from `git status`.
